# 알고리즘

## 1. 점근적 표기법

```
알고리즘의 성능(주로 실행 시간이나 메모리 사용량)을 데이터의 개수($n$)가 무한히 커질 때의 흐름(증가 추세)으로 평가하고 표현하는 수학적 방법
```

### 기본 전제 ($n$과 다항식)

- 여기서 $n$은 **처리해야 할 데이터의 개수**입니다.
- 예로 든 식 $n^3 + n^2 + n - 1$은 데이터가 늘어날 때 연산 횟수가 어떻게 늘어나는지를 보여주는 복잡한 수식입니다. 하지만 데이터가 아주 많아지면 뒤에 붙은 작은 항들은 의미가 거의 없어지고, **가장 차수가 큰 녀석($n^3$)이 전체 속도를 쥐락펴락**하게 됩니다.

---

### $O$ 표기법 (빅-오, Big-O) : **"최악의 경우에도 이보단 빠르다!" (상한)**

- **뜻:** 알고리즘의 최대 속도 제한(상한)을 나타냅니다. "아무리 오래 걸려도 이 정도 시간(차수) 안에는 끝난다"는 의미예요.
- **비유:** 자동차로 서울에서 부산까지 갈 때, "최대 5시간 안에는 도착한다"고 말하는 것과 같습니다. (실제로 3시간 만에 갈 수도 있지만, 5시간보다는 확실히 적게 걸린다는 보장이죠.)
- **예시:** $n^3 + n^2 + n - 1$에서 가장 큰 힘을 가진 건 $n^3$이므로, 이 식의 빅-오 표기법은 $O(n^3)$이 됩니다. (보통 개발할 때는 가장 타이트하고 정확한 이 빅-오 표기법을 가장 많이 씁니다.)

---

### $\Omega$ 표기법 (빅-오메가, Big-Omega) : **"최소한 이만큼은 걸린다!" (하한)**

- **뜻:** 알고리즘의 최소 속도(하한)를 나타냅니다. "아무리 빨라도 적어도 이 정도 시간(차수)은 무조건 걸린다"는 의미입니다.
- **비유:** 서울에서 부산까지 갈 때, "최소한 3시간은 걸린다"고 말하는 것과 같습니다. (차량이 막히면 더 걸릴 수 있지만, 순간 이동을 하지 않는 이상 3시간보다 빨리 갈 수는 없다는 뜻입니다.)
- **예시:** $n^3 + n^2 + n - 1$은 적어도 $n^3$만큼의 성장은 하므로, $\Omega(n^3)$뿐만 아니라 $\Omega(n)$, $\Omega(\log n)$ 등도 이론적으로는 "그것보단 오래 걸린다"는 말이 되므로 모두 맞는 표현이 됩니다.

---

### $\Theta$ 표기법 (빅-세타, Big-Theta) : **"정확히 이만큼 걸린다!" (평균/중간)**

- **뜻:** 위와 아래가 딱 맞아떨어져서, **알고리즘의 성장이 정확히 특정 함수와 일치**함을 나타냅니다.
- **비유:** 서울에서 부산까지 갈 때, "정확히 4시간이 걸린다"고 딱 잘라 말하는 것입니다. (상한과 하한이 만나는 지점)

---

### 💡 한 줄 요약

- **빅-오($O$):** "가장 나쁠 때 이 정도 걸려!" (**최악의 성능** 측정용으로 개발에서 가장 많이 씀)
- **빅-오메가($\Omega$):** "가장 좋을 때도 최소 이만큼은 걸려!" (**최소 성능**)
- **빅-세타($\Theta$):** "위아래 딱 맞아떨어져서 정확히 이 정도야!" (**평균/일치**)

## 2. 시간 복잡도

### 1. 시간 복잡도(Time Complexity)의 개념

- **정의**: 코드의 실행 횟수를 일일이 세지 않고, 점근적 표기법을 통해 추상적으로 표현한 것입니다.
- **필요성**: 프로그램이 효율적으로 작성되었는지 확인하고, 동일한 일을 수행하는 코드 중 더 적은 연산을 필요로 하는 효율적인 코드를 파악하기 위해 사용됩니다.

---

### 2. 기본 연산의 시간 복잡도

- **대입 연산**: 변수를 만들고 값을 할당하는 과정 등은 단순하게 $O(1)$의 연산을 수행한다고 봅니다.
- **조건문**: 단순하게 두 값을 비교하는 연산을 수행하므로 조건문 역시 $O(1)$의 시간 복잡도를 가집니다.

---

### 3. $N$의 범위에 따른 알고리즘 시간 복잡도 선택 가이드

보통 `for` loop를 **1억 번 도는 데 약 1초**가 걸린다는 기준을 바탕으로, 제한 시간이 1초일 때 $N$의 범위에 따라 사용 가능한 시간 복잡도를 빠르게 파악할 수 있습니다.

- $N \le 10$: $O(N!), O(2^N), O(3^N)$
- $N \le 20$: $O(2^N)$
- $N \le 100$: $O(N^4)$
- $N \le 500$: $O(N^3)$
- $N \le 1,000$: $O(N^2), O(N^2 \log N)$

### 🧠 핵심 요약: 이 표가 의미하는 것

컴퓨터가 **1초에 약 1억 번($10^8$)의 연산**을 처리할 수 있다고 가정할 때, "제한 시간 1초 안에 문제를 풀기 위해, 입력값($N$)의 크기에 따라 최대 어떤 연산 횟수(시간 복잡도)의 알고리즘을 써야 하는지"를 알려주는 기준표입니다.

---

### 📊 단계별 상세 설명

- **$N \le 10$ : $O(N!), O(2^N), O(3^N)$**
- **의미 및 이유**: 팩토리얼($N!$)이나 지수($2^N, 3^N$) 형태는 **연산 횟수가 폭발적으로 증가하는 가장 느린 알고리즘**입니다.
- 예를 들어 $10!$은 약 360만 번이지만, 여기서 숫자가 조금만 커져도 연산이 수천만~수억 번을 넘어가므로, **$N$이 10 이하로 아주 작을 때만** 1초 안에 통과할 수 있습니다.

- **$N \le 20$ : $O(2^N)$**
- **의미 및 이유**: $N=20$일 때 $2^{20}$은 약 100만 번의 연산입니다.
- 지수 함수는 $N$이 1씩 늘어날 때마다 연산량이 2배씩 곱해지므로, $N=30$만 되어도 10억 번을 넘어 1초를 초과하게 됩니다. 따라서 $N \le 20$ 정도일 때만 안전하게 쓸 수 있습니다.

- **$N \le 100$ : $O(N^4)$**
- **의미 및 이유**: 4중 반복문 형태인 $O(N^4)$를 뜻합니다.
- $100^4$은 정확히 1억 번($10^8$)의 연산이 되므로, 제한 시간 1초의 마지노선에 걸치게 됩니다.

- **$N \le 500$ : $O(N^3)$**
- **의미 및 이유**: 3중 반복문 형태인 $O(N^3)$을 뜻합니다.
- $500^3$은 약 1억 2천만 번의 연산으로, 1초 기준인 1억 번에 근접하여 제한 시간 내에 겨우 또는 안전하게 통과할 수 있습니다.

- **$N \le 1,000$ : $O(N^2), O(N^2 \log N)$**
- **의미 및 이유**: 2중 반복문 형태인 $O(N^2)$ 등을 뜻합니다.
- $1,000^2$은 약 100만 번($10^6$)의 연산밖에 되지 않으므로, 1억 번에 비해 턱없이 여유롭습니다. 따라서 1초 안에 아주 안전하게 결과를 낼 수 있습니다.

---

### 💡 코딩 테스트를 위한 팁

알고리즘 문제를 풀 때 가장 먼저 해야 할 일은 "문제에 제시된 $N의 최대 범위$"를 확인하는 것입니다. 만약 $N$이 1,000이라면 $O(N^2)$ 알고리즘을 떠올려야 하고, $N$이 20 이내라면 완전탐색이나 백트래킹($O(2^N)$ 등)을 의심해 볼 수 있습니다!
